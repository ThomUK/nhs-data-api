Errors

Errors use standard HTTP status codes and a JSON body with a detail field: a message, or for invalid parameters a list of problems. Error responses are never cached (Cache-Control: no-store). A missing row is not an error: a provider that did not submit has no row, never a zero.

Status codes
200Success
404Not found
422Invalid request
429Too many requests (planned)
503Data not available
Error body
{
  "detail": "RJX is not an organisation in the statistics"
}

404Not found

The dataset or organisation does not exist, or nothing matches the filters. When the organisation exists but has no data for the requested month, the message says so: it may not have submitted, or may have been recoded.

What to do: Check the code with /v1/organisations, or see /v1/rtt/submissions for that month.

Request
curl "https://<api-host>/v1/rtt/metrics?view=provider&org=RX1&period=2026-09-01"
Response · 404
{
  "detail": "RX1 has data in this view, but not for the requested period. If it is a provider, it may not have submitted that month, or may have been recoded; see /v1/rtt/submissions."
}
Request
curl "https://<api-host>/v1/organisations/XXX"
Response · 404
{
  "detail": "XXX is not an organisation in the statistics"
}

422Invalid request

A parameter is not valid: an unknown measure id, a value outside the allowed list, or a badly formed date. Unknown measures return a message; other validation errors return a list of problems, each with the parameter's location and a message.

What to do: Correct the parameter. Allowed values are listed on the Endpoints page.

Request
curl "https://<api-host>/v1/rtt/metrics?measures=waiting_list"
Response · 422
{
  "detail": "unknown measures ['waiting_list']; see /v1/datasets/rtt"
}
Request
curl "https://<api-host>/v1/rtt/metrics?view=trust"
Response · 422
{
  "detail": [
    {
      "type": "literal_error",
      "loc": [
        "query",
        "view"
      ],
      "msg": "Input should be 'national', 'provider', 'provider_icb', 'population_icb' or 'population_sub_icb'",
      "input": "trust",
      "ctx": {
        "expected": "'national', 'provider', 'provider_icb', 'population_icb' or 'population_sub_icb'"
      }
    }
  ]
}

429Too many requests (planned)

Anonymous and per-key rate limits will return 429 with a Retry-After header.

What to do: Wait for the number of seconds in Retry-After, or use an API key.

No live example.

503Data not available

The service is running but its data has not been loaded (for example during setup).

What to do: Retry later.

No live example.
